# 05 · 成果转化路线图

> 目标：让「柳树沟村」这一个项目，同时产出 **软著 + 论文 + 毕设 + 求职作品集** 四项成果。
> 原则：**一次投入，四处复用**。凡是要重复劳动的路径，直接砍掉。
> 编制日期：2026-11-07

## 一、先说真话：四件事的价值不是等价的

| 目标 | 真实价值 | 成本 | 周期 | 复用度 | 建议 |
|---|---|---|---|---|---|
| **软件著作权** | ★★★★★ 唯一的国家级证书，毕设成果证明、简历硬通货 | 免费（自办） | 30–60 工作日 | 高 | **立刻办** |
| **毕业设计** | ★★★★★ 必须完成，且能 100% 复用本项目 | 时间 | 2027.09–2028.06 | 极高 | **必然做** |
| **求职作品集** | ★★★★★ 唯一能直接换钱的 | 时间 | 2027 秋招 | 高 | **重点打磨** |
| **期刊论文（普刊）** | ★★☆☆☆ 版面费 1500–4000 元，对求职加成接近于零 | 钱 + 时间 | 4–8 个月 | 中 | **看情况，最后做** |

**一句话：软著是白捡的，毕设是必须的，作品集是换钱的，论文是花钱买名声的。**

普刊不是不能发，而是**先问自己三个问题，有一个答不上就先别发**：

1. 学校有明文规定：发论文能加综测分 / 评奖学金 / 保研加分？
2. 学院有老师愿意挂名推荐（有推荐人，录用率高一大截）？
3. 2000 块版面费掏了不影响生活？

三个都答"是"，再动手。答不上，就把这笔钱和时间扔到作品集上，回报率高得多。

## 三、第一优先级：补「对比实验」数据（一次性投入，四处复用）

这是**唯一一件必须先做的事**。没有它，论文写不成、答辩没底气、简历没数字。

### 测什么

| 组别 | 实现方式 | 说明 |
|---|---|---|
| A 组 | 贴图草（PlaneGeometry + alpha 贴图） | 项目最初版 |
| B 组 | 几何草 · 低密度（约 2 万根） | 中间版 |
| C 组 | 几何草 · 15 万根实例化（当前版） | 现版本 |

### 指标（每档跑 60 秒取均值）

| 指标 | 采集方式 |
|---|---|
| 平均 FPS / 1% Low FPS | Chrome DevTools → Performance → Frames |
| Draw Call 数 | `renderer.info.render.calls` |
| 三角形数 | `renderer.info.render.triangles` |
| 首帧时间 | `performance.now()` 到首帧渲染完成 |
| 显存占用 | Chrome 任务管理器 → GPU 内存 |
| 内存占用 | `performance.memory.usedJSHeapSize` |

### 设备（至少两台，这是审稿人最爱挑的）

1. Apple A18 Pro / 8 GB（已有）
2. 普通 Windows 笔记本（学校机房即可，集显最好——这才是真实用户设备）

### 产出

一张 6 行 × 4 列的表 + 一张折线图。**这张表同时是：论文的"实验与分析"、毕设的"性能测试"、简历的"优化成果"、答辩 PPT 的一页。**

## 四、第二优先级：软件著作权（免费，立刻办）

### 基本信息

- 登记机构：中国版权保护中心（https://www.ccopyright.com.cn）
- 方式：**自行在线申请，不收费**（2017 年起国家取消登记费）
- 周期：受理后约 30–60 个工作日
- 加急：代理 300–1500 元，可缩短至 3–15 工作日（不急就别花）

### 软件名称（重要，不能乱起）

✅ 推荐：**柳树沟村三维气象可视化系统 V1.0**
❌ 禁用：带"数字孪生"字样

理由：软著要和论文、毕设口径一致。软著写"数字孪生"、论文写"可视化系统"，将来万一被追问，自己打自己脸。

### 材料清单

| 材料 | 要求 | 现状 |
|---|---|---|
| 申请表 | 在线填 | 待填 |
| **源代码文档** | 前 30 页 + 后 30 页，共 60 页，每页 ≥50 行 | **4468 行 JS 正好够** |
| 软件说明书 | 含功能界面截图，≤60 页 | 可由 `docs/01-管理员手册.docx` 改造 |
| 身份证明 | 身份证扫描件 | 待备 |

### ⚠️ 源代码的两个坑

1. **绝不能把 `vendor/` 目录（three.js）放进源代码文档**。那是 MIT 协议的第三方库，放进去等于声称自己写了 three.js，权属直接出问题。
2. **`assets/` 里的 HDRI 和 PBR 贴图同理**——那是下载的素材，不是代码，不提交，但要在说明书里注明来源。

**只提交 `js/*.js` + `css/style.css`，共 4836 行。** 页眉标注软件名称 + 版本号，连续页码。

## 五、第三优先级：求职作品集（换钱的那件）

投简历时，HR 和面试官不会点开 GitHub 读代码。他们看三样：

### 1. 一段 90 秒的演示视频（最重要）

剧本：
- 0–15s：上帝视角俯瞰全村，时间轴从春拖到冬（一镜到底，别剪）
- 15–35s：切第一人称，走一段路，点一棵树弹窗
- 35–55s：天气切到雨、再切雪（屋顶积雪、路面积水）
- 55–75s：夜晚，路灯亮起
- 75–90s：字幕一行——「8760 小时真实气象数据驱动 · 单文件 15MB · 双击即开」

**不要配 AI 配音，不要加花哨转场。** 干净的原画录屏 + 字幕，比什么都强。

### 2. README 顶部三行

现在的 README 是给开发者看的。改成给面试官看的：

```
柳树沟村 · 三维气象可视化系统
Three.js + 甘肃岷县 2025 年 8760 小时真实气象数据
15 万根 GPU 实例化植被 · GTAO 后处理 · 单文件离线运行
```

### 3. 简历上的一行 + 面试时的三个故事

**简历写法**（不要写"使用了 Three.js"，要写结果）：

> 独立完成三维乡村气象可视化系统（Three.js / WebGL），接入 8760 小时真实气象数据驱动场景状态，
> 通过实例化渲染将植被绘制调用从 2200 次降至 94 次，单文件 15MB 离线运行，已获软件著作权登记。

**面试必须讲透的三个技术点**（讲不透 = 露馅）：

| 技术点 | 要讲清的因果链 |
|---|---|
| 15 万根草的实例化 | 为什么贴图不行 → 为什么实例化降 draw call → 为什么用顶点着色器做风动 |
| GTAO 深度预通道污染 | 加透明面片后墙面为什么出现黑白斑块 → 为什么改成材质内烘暗化 |
| `Number(null) === 0` 的机位 bug | 调试参数判断写错 → 为什么相机默认贴地 → 怎么定位的 |

**这三个故事比任何证书都值钱。** 它们证明你是"能调试的人"，不是"能提需求的人"。

## 六、第四优先级：论文（可选，看第一节的三个问题）

### 前提条件（缺一不可）

- [ ] 对比实验数据已完成
- [ ] 题目已改（卸掉"数字孪生"）
- [ ] 素材授权声明已写
- [ ] 有推荐人

### 题目（二选一）

> 《基于 WebGL 与真实气象序列的乡村三维可视化系统设计与实现》
> 《逐小时气象序列驱动的三维乡村场景状态映射方法》

### 必须补的东西

1. **气象→场景映射模型**：把"气温/云量/降水/风速 → 光照强度/雾浓度/积雪覆盖/土壤湿度"写成有阈值、有公式的表。**这是唯一能把工程包装成方法的缝。**
2. **精度校验**：驱动出的日照时长/温度曲线 vs 岷县气象站实测，算 MAPE。
3. **素材授权声明**：HDRI / PBR 贴图来源与许可（Poly Haven = CC0）。
4. **局限章节**：明写"非实时数据、虚拟场景、无反向控制"——主动交代，比被审稿人挑出来强。

### 投稿梯度

| 层级 | 期刊举例 | 现版本 | 需补 |
|---|---|---|---|
| 普刊 | 《现代信息科技》《软件》《电脑知识与技术》《农业工程技术》 | 有戏 | 实验数据 + 改题 |
| 学报 | 本科院校学报 | 勉强 | 上述 + 方法创新 |
| 核心 | 《农业工程学报》《计算机应用研究》 | 无望 | 需重做研究设计 |

## 七、红线（碰了前功尽弃）

1. **任何正式材料里，不能出现"数字孪生"这四个字。** 软著、论文、毕设、简历，一律用"三维可视化系统 / 气象驱动可视化"。
2. **不能声称 `assets/` 里的素材是自己做的。** 论文和软著说明书都要注明来源。
3. **不能把 three.js 源码当自己的代码提交。**
4. **不能把 AI 生成的截图当成"实机运行效果"宣传。** 现在是真的能跑，就老老实实录屏。
5. **简历上不要写"精通 Three.js"。** 写"能独立完成基于 Three.js 的三维可视化系统开发"，前者一问就穿帮，后者站得住。
