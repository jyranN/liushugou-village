# 柳树沟村 · 下一阶段施工计划

> **状态（2026-11-08）**：本计划列入的九项均已在 **v1.1** 完成并验收。本文保留为施工前的计划稿，
> 文中"没有河""没有石墩""电线杆未恢复"等描述的是 **v1.1 之前** 的状态，不是当前状态；
> 当前实现以 `docs/src/02-项目手册.md` 与代码为准。
>
> 面向 v1.1 ~ v1.3。排序原则：先修"错的"，再修"慢的"，再动"地基"，最后加"内容"。
> 顺序不是按重要性排的，是按"改动会不会牵连别人"排的。

## 一、为什么是这个顺序

九项需求混着做，必然返工。原因是它们的依赖关系不对等：

| 类型 | 项 | 特点 |
|---|---|---|
| 修错 | WASD 方向、进村朝向 | 不修，后面所有第一人称验收都不可信 |
| 修慢 | 卡顿、低配降级 | 不修，加入内容后无法判断是"内容太重"还是"地基太薄" |
| 动地基 | 加山、加河 | `heightAt` 一改，全村物体重新落位；必须先做，否则石头、树、动物要摆两遍 |
| 加内容 | 动物、石头、细节、晴天档、巡游 | 只往上叠，不动别人；地基定了才好摆 |

一句话：**先让方向对、帧率够，再动地形，最后堆东西。**

```
第 0 批  修错     0.5 天
第 1 批  性能     1.5 天
第 2 批  地基     3 天
第 3 批  内容     3 天
```

## 二、第 0 批 · 修错（0.5 天）

### 0-A 第一人称左右反

**文件**：`js/controls.js` 第 209–211 行（`_updateWalk`）

**根因**：相机朝向 `forward = (sin yaw, 0, cos yaw)`，其右向应为 `right = forward × up = (-cos yaw, 0, sin yaw)`。现有公式给的是 `(cos yaw, 0, -sin yaw)`，正好差一个负号，所以 A/D 互换。

**改法**：

```js
// 改前
const sin = Math.sin(this.yaw), cos = Math.cos(this.yaw);
const wx = ix * cos - iz * sin;
const wz = -ix * sin - iz * cos;

// 改后：right = forward × up = (-cos, 0, sin)
const sin = Math.sin(this.yaw), cos = Math.cos(this.yaw);
const rx = -cos, rz = sin;
const fx = sin,  fz = cos;
const wx = ix * rx - iz * fx;
const wz = ix * rz - iz * fz;
```

**验证**：`yaw = 0` 时 W 应走 `(0, 0, +1)`、D 应走 `(-1, 0, 0)`（因为相机朝 +z 时屏幕右是 −x）。四个键全试，不能只试左右。

**注意**：摇杆 `joy.x` 与之共用同一套 `ix`，改完要在触屏上再验一次方向。

### 0-B 进第一人称背对村子

**文件**：`js/controls.js` 第 123 行（`enterWalk`）

**根因**：落点取在目标点 `+z` 侧 14 米，正确朝向应是 `atan2(dx, dz) = atan2(0, -14) = π`（面向 −z 的村子）。代码多加了一个 `Math.PI`，变成 2π ≡ 0，于是面向 +z，背对村子。

**改法**：删掉 `+ Math.PI`。

```js
this.yaw = Math.atan2(t.x - this.walk.x, t.z - this.walk.z);
```

**注意**：`exitWalk` 第 138 行的 `theta = yaw + Math.PI` 是对的，不要动。只改 `enterWalk` 一处。

**验收**：按 F 进入后，画面里应当是村子（房屋、主路），不是背后那片空地。

## 三、第 1 批 · 性能地基（1.5 天）

场景只有 120 个 Mesh、6 个 InstancedMesh、三角形不足一万，所以**卡的不是几何量，是填充率**：全屏后处理 + 过高的像素比 + 大面积阴影贴图。

### 1-A 像素比上限 1.75 → 1.25

**文件**：`js/main.js` 第 29 行

```js
const MAX_SCALE = Math.min(window.devicePixelRatio || 1, 1.25);
```

Retina 屏上 1.75 等于 3360×1890 在跑，降到 1.25 后像素数减少约 49%，观感差异很小。
`MIN_SCALE` 保持 0.62 不变。

### 1-B GTAO 默认关闭

**文件**：`js/main.js` 第 63–75 行

室外大场景里 GTAO 收益有限，却要跑法线/深度预通道 + AO + 去噪三趟全屏 pass，是最重的一项。

改为默认不加，需要时用 `?ao=1` 开启：

```js
if (QS.has('ao')) composer.addPass(gtaoPass);
```

**注意**：关掉后画面会略"平"，需要把 `toneMappingExposure`（第 41 行）从 1.16 微调到 1.20，并用截图对比确认没有发灰。

### 1-C 阴影降配

**文件**：`js/world.js` 第 204 行、`js/main.js` 第 43 行

```js
// world.js
sun.shadow.mapSize.set(2048, 2048);   // 原 3072

// main.js
renderer.shadowMap.type = THREE.PCFShadowMap;   // 原 PCFSoftShadowMap
```

**注意**：改完要复查 `sun.shadow.normalBias`（现为 0.035），降分辨率后自阴影瑕疵会变明显。

### 1-D 低配降级开关（原需求"低配降级"）

**文件**：`js/main.js`（新增 `setQuality`）+ `js/ui.js` + `index.html`

三档，写入 `localStorage`：

| 档位 | 像素比 | GTAO | Bloom | 阴影 |
|---|---|---|---|---|
| 流畅 | 1.0 | 关 | 关 | 1024 |
| 均衡（默认） | 1.25 | 关 | 开 | 2048 |
| 精致 | 1.5 | 开 | 开 | 3072 |

实现要点：`gtaoPass.enabled`、`bloomPass.enabled`、`renderer.setPixelRatio`、`sun.shadow.mapSize.set` 都要在切换时一并更新，并 `dispose` 旧的 shadow map 后重建，否则新尺寸不生效。

自适应分辨率逻辑（第 272–288 行）保留，它是兜底。

### 1-E 晴天 / 天气预设档

**文件**：`js/climate.js`（新增 `findPreset()`）+ `js/ui.js`

不要伪造晴天——从 8760 条真实记录里挑：

- 晴：`cloud < 10 && precip === 0 && 9 ≤ hour ≤ 16`，优先取 6–8 月
- 阴：`cloud > 85 && precip === 0`
- 雨：`precip` 全年最大值那一刻
- 雪：`snowfall > 0 && temp < 0` 中雪量最大的一刻

数据层算出来，不写死日期——换年份这套还能用。

**界面**：时间条右侧加四个小按钮，点击 `clock.hour = 目标小时`。

**注意**：切换后需要让 `updateEnvironment` 跑一帧（`clock` 跳变会自动触发），并提示"2025 年真实记录"，别让观众误以为是假天气。

**验收**：点"晴"能看见蓝天白云和清晰远景；点"雪"地面有积雪、有雪片。

## 四、第 2 批 · 动地基（3 天）

### 2-A 村东加山、山腰建庙

**文件**：`js/world.js` 第 32 行 `heightAt`、新增"山体与庙"段落

**现状**：`heightAt` 在 100 米半径内强制全平（`flat = 0`），250 米外才起山。所以村内平、远处山，中间这截空着。

**选址**：中心 `(170, 20)`，底半径 75 米，高 58 米。

算过的边界：山体西缘落在 x = 95，而最东的田是西梁地（x 到 91）、北湾地（x 到 90）。**刚好不压田**，从村里看山就在 95 米外，"旁边"够近。

**改法**（`heightAt` 内，return 之前）：

```js
const mx = x - 170, mz = z - 20;
const md = Math.hypot(mx * 1.15, mz * 0.85);   // 稍作椭圆，别太规整
const hillF = smoothstep(75, 22, md);          // 内 1 外 0
const hill = hillF * hillF * 58;               // 二次衰减：山脚缓、山腰陡
return ridge * flat * flat + ripple * Math.min(1, flat * 3) + hill;
```

**注意**：
1. **远山网格会跟着变**。远景那段（第 270 行）内圈调用同一个 `heightAt` 并下潜 4 米，新增的山在地形网格覆盖范围内（±306），会被压在下面，不会出现迷彩斑块 —— 但改完必须俯瞰检查一次。
2. **散树与草**在村外撒到 ±118，新山的东坡会落在撒点范围外，西坡（95–118）的树会自动按 `heightAt` 落地，无需改动。草的撒点若覆盖到山坡，需要排除坡度大于 25° 的区域，否则草会悬空。
3. **阴影相机范围**要扩到 ±200，否则山不投影，山脚会像贴纸。

**庙**：位置取山腰 `(140, 20)`，小体量 6×5 米，硬山顶 + 门 + 匾 + 香炉 + 一棵老树。石阶从 `(95, 20)` 修到庙门，每级按 `heightAt` 落地，约 40 级。

**山的材质**：现地面用草地贴图，山上要按高度混：草 → 土（`#6f6047`）→ 岩。用顶点色实现，与现有"按海拔压暗"那段（第 256–268 行）合并写。

**验收**：从村口远看有山；第一人称走到山脚能沿石阶上去；山上没有浮空的树。

### 2-B 村西开河

**先说个发现**：数据里早就埋了河的伏笔——`F-05 水磨坊`（`[-62, 62]`，备注"水轮残缺，仅存石磨"）、`L-06 河滩地`（`[-86, 96]`）。**没有河，这两条档案是空的**。所以河不是新加设定，是补上原有设定。

**走向**：村西，近南北，微弯。从 `(-105, -130)` 到 `(-98, 130)`，河宽 8 米，河床比岸低 2.2 米。

**改法**（`heightAt` 内追加）：

```js
const riverX = -101 + Math.sin(z * 0.011) * 7;   // 缓慢摆动，不像水渠
const rd = Math.abs(x - riverX);
const riverF = smoothstep(13, 2, rd);            // 中心 1，岸线 0
h -= riverF * 2.2;
```

**水面**：单独一层，`y = 河床 + 1.6`。材质用 `MeshStandardMaterial`（透明 0.78、`roughness` 0.15、`metalness` 0），靠 HDRI 的环境反射出天光，**不要做实时反射**——太贵。法线贴图沿 V 轴缓慢滚动模拟流水。

**三个必须处理的问题**：

1. **水磨坊离河 38 米**。必须挪到岸边：`[-88, 62]`，水轮朝西。同时改 `data.js` 里的 `pos`，档案卡里的描述不用动。
2. **河滩地会被河切开**。`L-06` 现在 `pos[-86,96] size[32,24]`，x 到 −102，正好压在河面上。改为 `pos[-76,96] size[22,20]`，退到河东岸。
3. **草不能长在河里**。几何草的撒点（第 1542 行起）要排除 `rd < 9` 的区域，否则水面会浮着一层草。

**桥**：村西小路跨河处修一座漫水桥（西北旱地小河常见，比石拱桥更符合当地），3 孔，桥面略高于常水位。

**验收**：第一人称从村里走到河边，岸线平滑没有断崖；水面有反光；河里没有草。

## 五、第 3 批 · 加内容（3 天）

### 3-A 树下石头、石碾、水窖

**又一个发现**：`data.js` 里村口两棵树的备注已经写着——

> 村口老杨树：`村口地标，树下有石墩，夏天村人乘凉`
> 村口老槐：`树下曾挂铁钟，旧时召集村民所用`

**但场景里光秃秃的，一块石头都没有。** 档案卡在骗人。这不是"缺内容"，是数据与场景不一致，优先级比新加设定更高。

**做法**（`js/world.js` 第 1448 行"村内支路与杂物"段内新增）：

- 石墩：`CylinderGeometry(0.28, 0.34, 0.45, 8)`，坐高 0.45，围树干摆 4–6 个，每个随机旋转 5°、顶点位置抖 ±0.03
- 石碾：碾盘（半径 1.2 的矮圆柱）+ 碾磙（横躺圆柱）+ 木架
- 水窖口：地面内凹圆口 + 铸铁盖 + 辘轳架。陇中缺水，家家有水窖，这是地方性
- 材质复用现成的 `stoneT`，加顶点色做深浅不均

**注意**：石墩要放在树冠投影下（半径 2–3 米），不要压在树根上；每个都加 `proxy()` 使其可点击，档案写真实民俗（"石墩为清末凿制，原有六只，现存四只"这类）。

### 3-B 动物升级

**文件**：`js/world.js` 第 1103–1147 行 `buildAnimal`

**现状**：胶囊体身体 + 方块头 + 4 根圆柱腿。目标是"可信低模"，不做写真。

**改法**：

| 部位 | 现状 | 改成 |
|---|---|---|
| 身体 | Capsule 6×10 段 | 8×12 段，顶点加轻微起伏；牛加肩峰（矮锥） |
| 头 | Box | 球体压扁 + 前伸的口鼻（短圆柱） |
| 脖子 | 无 | 短圆柱连接，牛粗短、羊细长 |
| 耳朵 | 无 | 两片扁锥，外翻 |
| 尾巴 | 无 | 细圆柱 + 末端毛球，带摆动 |
| 腿 | 单段直插 | 分大腿/小腿两段，中间加膝球 |
| 毛色 | 纯色 | 顶点色做背深腹浅 |

**性能约束（重要）**：每只动物如果拆成 12 个 Mesh，16 头就是 192 个 draw call，比现在翻一倍。

推荐做法：**每只动物合并成一个 BufferGeometry**（`BufferGeometryUtils.mergeGeometries`），只保留整体位置与朝向的动画，不做腿部骨骼动画。16 头 = 16 个 draw call，可接受。
牛的转头吃草可以用整体轻微俯仰模拟，不做独立骨骼。

**验收**：第一人称走近牛棚，能看出是牛；帧率不比改前低。

### 3-D 一键巡游

**文件**：`js/main.js`（新增 `Tour` 类）+ `js/ui.js`

**做法**：
- 一条 `CatmullRomCurve3` 相机路径 + 每段一个注视目标 + 每段时长
- 30 秒 5–6 个镜头：村口老杨树 → 主路推进 → 某户院门 → 晒场 → 山腰庙 → 拉高俯瞰全村
- 转场用 `easeInOut`，不要匀速
- 巡游中禁用用户输入，`Esc` 或点击任意处中断
- 字幕用底部 `hint` 元素

**注意**：路径高度必须逐点取 `heightAt` 再加 1.8 米，否则会穿地或飞在半空；与第一人称模式互斥，进入巡游前先 `exitWalk()`。

**验收**：按一键，30 秒内把村子最好的一面走完，中途不穿模、速度不忽快忽慢。

## 六、全局风险

1. **每改一次 `heightAt`，都要跑 2-C 的落位回归**。这是唯一会全场景牵连的改动。
2. **加法都要先算 draw call**。现在 120 个 Mesh 还能跑，加到 300 个就回到改之前的状态。
3. **每批做完先截图存档**，再进下一批。否则出问题分不清是哪一批引入的。
4. **文档要跟着改**。这次已经发现三处文档与实现不一致（电线杆、河、石墩），都源于"先写文档后改代码"。
