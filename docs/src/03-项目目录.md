# 柳树沟村 · 数字村落 项目目录

## 一、说明

本文档描述项目的**文件组织方式**：每个目录放什么、每个文件负责什么、命名与编号怎么定、打包时哪些进交付、哪些只是开发过程产物。

阅读顺序建议：先看第二章的交付包结构，再看第三章的工程根目录，最后按需要查具体文件表。

## 二、交付包结构

对外分发的压缩包 `柳树沟村-项目包-2026-11-06.zip`（约 23 MB）解压后是：

```
柳树沟村-项目包-2026-11-06/
├── 柳树沟村.html              单文件离线版，双击运行（15 MB）
├── 使用说明.txt               一页纸快速上手
├── 预览图/
│   ├── 俯瞰.png
│   └── 近景.png
└── 源码/
    ├── index.html             开发版入口
    ├── package.json           依赖声明（仅 esbuild）
    ├── package-lock.json
    ├── js/                    源码（9 个模块，共 4235 行）
    ├── css/style.css
    ├── data/minxian-2025-raw.json
    ├── assets/                HDRI 与 PBR 贴图（9.8 MB）
    ├── vendor/                three.js r160 及后处理（1.9 MB）
    └── tools/                 构建、截图、自检脚本
```

包内**不含** `node_modules`（首次 `npm install` 生成）与历史截图 `preview-*.png`。

## 五、数据文件

`data/minxian-2025-raw.json`（436 KB）是 Open-Meteo 的原始返回，未做任何加工。

### 5.1 结构

```json
{
  "hourly": { "time": [...8760], "temperature_2m": [...], ... },
  "daily":  { "time": [...365], "sunrise": [...], "sunset": [...], ... }
}
```

### 5.2 hourly 字段

| 字段 | 单位 | 用途 |
|---|---|---|
| time | ISO 字符串 | 时间索引，2025-01-01T00:00 起逐小时 |
| temperature_2m | ℃ | 气温，决定雨/雪与体感 |
| relative_humidity_2m | % | 湿度，驱动雾浓度 |
| precipitation | mm | 降水，驱动雨强与地面湿润 |
| cloud_cover | % | 云量，驱动天空覆盖度与光照衰减 |
| weather_code | WMO 代码 | 天气现象文案 |
| wind_speed_10m | km/h | 风，驱动草与雨丝倾斜 |
| snowfall | cm | 降雪，驱动积雪累积 |
| is_day | 0/1 | 数据源的昼夜标记（渲染以太阳位置为准） |

### 5.3 daily 字段

`time`、`sunrise`、`sunset`、`temperature_2m_max`、`temperature_2m_min`。日出日落用于校验天文解算，不直接驱动光照。

## 八、工具脚本 `tools/`

| 脚本 | 用途 | 用法 |
|---|---|---|
| build-standalone.mjs | 打包单文件离线版：esbuild 打 IIFE，内联 JS/CSS/气候 JSON/贴图 data URI | `node tools/build-standalone.mjs` |
| qa.mjs | 自动化验收：连 CDP，检查首屏、拾取、第一人称、报错 | `node tools/qa.mjs 9222 /tmp` |
| shot.mjs | 指定时刻与机位截图 | `node tools/shot.mjs "?day=131&hour=10" out.png 55` |
| probe.mjs | 在已打开页面执行表达式，读运行时状态 | `node tools/probe.mjs "window.__app.clock.hour"` |
| eval-shot.mjs | 执行一段 JS 后截图 | `node tools/eval-shot.mjs "..." out.png 8` |
| export-engine.mjs | 导出 UE / Unity 可读的布局与气象 CSV | `node tools/export-engine.mjs` |

### 8.1 截图脚本的注意事项

- 页面若是 `document.visibilityState === 'hidden'`，`requestAnimationFrame` 会停摆，导致截图超时；脚本必须先 `Page.bringToFront` 并启用焦点模拟。
- 软件渲染（SwiftShader）下首帧可能需要 30 秒以上，等待时间不要低于 45 秒。
- 必须关闭缓存（`Network.setCacheDisabled`），否则会截到旧 JS 的画面。

## 十、编号规则

所有可点击对象都有稳定 ID，格式为 `前缀-两位序号`：

| 前缀 | 类型 | 范围 | 示例 |
|---|---|---|---|
| H | 民居 | H-01 ~ H-14 | H-03 王建国宅 |
| T | 树木 | T-01 ~ T-94 | T-27 老槐树 |
| A | 家畜 | A-01 ~ A-16 | A-05 秦川牛 |
| F | 公共设施 | F-01 ~ F-13 | F-07 路灯 |
| D | 地块 | D-01 ~ D-14 | D-02 当归地 |
| Y | 院落物件 | Y-01 ~ Y-09 | Y-04 水缸 |

编号在 `data.js` 中手工维护，`ALL_OBJECTS` 汇总后供拾取与档案卡使用。新增对象时：先在对应数组追加，再确认 `ALL_OBJECTS` 是否自动收集（当前为显式汇总，需要手动加一行）。
