# 柳树沟村 · AI 施工提示词手册

> **状态（2026-11-08）**：本手册配套的施工批次已在 **v1.1** 全部执行完毕。
> 文中出现的"现在没有河/没有石墩/水磨坊离河 38 米"等，都是当时用来描述 **改造前现状** 的提示词背景，
> 不代表当前版本；当前状态见《02-项目手册》与《04-项目日志》第十三章。
>
> 配套《05-施工计划》。每条提示词独立可用，复制粘贴即可，不需要你懂代码。
> 原则：一条只干一件事；干完必须自证；不自证的不算完。

---

## 一、使用规矩（三条，别嫌烦）

**1. 一条一次，别合并。**
把"修 bug"和"加山"写进同一个提示词，AI 会挑软的做，硬的那半边糊弄过去。一条干完、验完，再发下一条。

**2. 每条都要它自证。**
手册里每条都带了「自证」段落。项目自带 `tools/probe.mjs`（读页面内部状态）和 `tools/shot.mjs`（截图），够用了。**它说"已完成"不算数，贴出探针输出和截图才算。**

**3. 改坏了就回滚，别修。**
每批开工前先提交一次 git。改崩了 `git checkout .` 退回去重发提示词，比让 AI 在你的废墟上继续救火便宜得多。

> 让截图工具工作起来需要先开 Chrome 调试端口。提示词里已经写好了，AI 会自己起。

### P0 · 修第一人称方向（先做这条）

```
接通用开头。

【本次只做】修正第一人称的两个方向 bug，别的一律不动。

1. 按 D 键人往左飘、按 A 往右飘——左右是反的。找到控制行走移动方向的
   那段（controls.js 里 _updateWalk，约 209-211 行），把水平方向的右向量
   改成"相机朝向 × 世界上向量"的正确结果，使 A/D 与世界左右一致。
2. 按 F 进入第一人称时，人是背对村子站着的（面向村外空地）。原因是
   enterWalk 里 yaw 多加了一个 π（约 123 行）。删掉它。
   注意：exitWalk 里那句 theta = yaw + π 是对的，绝对不要一起改。

【自证】
- 用 probe.mjs 打印进入第一人称后的相机朝向向量和 yaw，确认朝向村中心
- 用 shot.mjs 截一张按 F 后的画面，我要能在图里看到房屋和主路
- 逐条回答：W/S/A/D 四个方向各走一步，人往哪边去？用文字描述方位
```

**验收**：截图上进村能看见房子；四个键各走一步，方向都对。

### P1 · 性能三刀

```
接通用开头。

【本次只做】降低渲染开销，让第一人称稳定 55 FPS 以上。不加任何新内容。

1. 渲染像素比上限从 1.75 降到 1.25（main.js 顶部 MAX_SCALE）。
2. GTAO 环境光遮蔽默认关闭，改成只有 URL 带 ao=1 时才启用。
   关掉后画面会发平，把曝光（toneMappingExposure，现 1.16）微调到 1.20 补回来。
3. 阴影贴图从 3072 降到 2048，阴影类型从 PCFSoft 换成 PCF。
   改完检查 shadow.normalBias（现 0.035），如果自阴影出现条纹或漏光就微调它。
4. 自适应分辨率那段逻辑保留不动，它是兜底。

【自证】
- 改前改后各截同一机位一张图（用 shot.mjs 固定 day/hour 参数），对比亮度
- 用 probe.mjs 连续读 FPS 三次（间隔 5 秒），把三个数贴出来
- 明确回答：改后画面有没有变灰、变平、出现自阴影瑕疵？有就说清在哪
```

**验收**：FPS 数字上去了；两张截图亮度接近，没发灰。

### P2 · 画质三档 + 天气预设档

```
接通用开头。

【本次只做】加两个界面功能，不动场景内容。

一、画质三档开关（界面右下，或设置里）
   流畅：像素比 1.0、无 GTAO、无泛光、阴影 1024
   均衡（默认）：像素比 1.25、无 GTAO、有泛光、阴影 2048
   精致：像素比 1.5、开 GTAO、有泛光、阴影 3072
   切换时要真正生效（阴影尺寸换了要重建贴图），选择记在 localStorage，刷新后保持。

二、天气预设档（时间条旁边四个小按钮：晴 / 阴 / 雨 / 雪）
   不要伪造天气。启动时从岷县 2025 那 8760 条真实记录里筛出四个时刻：
   - 晴：云量低于 10%、无降水、白天 9-16 点，优先取夏季
   - 阴：云量高于 85%、无降水
   - 雨：全年降水量最大的那一小时
   - 雪：有降雪且气温低于 0℃ 中雪量最大的一刻
   点击按钮把时间轴跳到该时刻。数据里现算，不要写死日期。

【自证】
- 四个按钮各点一次，各截一张图（共 4 张），我要看晴阴雨雪确实不一样
- 切到"流畅"档再切回"精致"，确认阴影和泛光真的跟着变
- 说明四个预设分别落在 2025 年哪一天几点，以及依据是什么
```

**验收**：四张图一眼能分出天气；切档有肉眼可见差别。

### P3 · 村东加山、山腰建庙

```
接通用开头。

【本次只做】加一座山和一座小庙。这是动地形，改完必须做全村落位检查。

一、山（改 heightAt）
   中心放在村子正东 170 米、南北居中偏北（坐标 170, 20），山脚半径 75 米，山顶高 58 米。
   山脚落在 x=95 附近——最东边的田到 x=91，两者不重叠，这个位置是算过的，不要放大半径。
   山形要二次衰减：山脚缓、山腰陡，不要做成规整的圆包。稍微压成椭圆，别太对称。

二、山体材质
   现在地面是草地贴图。山上要按高度渐变：草 → 土黄 → 岩石，用顶点色实现。
   和现有的"按海拔压暗"那段合并写，不要重复遍历顶点。

三、庙
   位置在山腰（约 140, 20），体量 6×5 米，硬山顶，有门、有小匾、门前香炉、旁边一棵老树。
   用现有的砖瓦木石贴图即可，不要引入新素材。
   从山脚 95,20 修石阶到庙门，约 40 级，每级按地形高度落地。

四、阴影
   现在阴影相机范围可能只覆盖村子，山在外面就不投影，山脚会像贴纸。把范围扩到能盖住山。

【自证】
- 从村口截一张远看山的图
- 用 probe.mjs 打印 x=95、x=170 两处的地形高度，确认山脚和山顶高度对
- 逐个检查：14 户房、14 块田、9 处设施有没有被山压到或半埋？列个表回答
- 第一人称走到山脚，截一张仰视山的图
```

**验收**：村里能看见山；山脚没有浮空的树；田地一亩没被埋。

### P4 · 村西开河

```
接通用开头。

【本次只做】在村西开一条河。这是动地形，改完必须做落位检查。

背景：数据里早就有"水磨坊（水轮残缺，仅存石磨）"和"河滩地"，但场景里没有河，
等于这两条档案是空的。这次是把欠的补上。

一、河道
   走向近南北，从村西北 (-105, -130) 到村西南 (-98, 130)，轻微摆动，不要笔直像水渠。
   河宽 8 米，河床比两岸低 2.2 米，岸坡要平滑过渡，不能出现断崖。

二、水面
   单独一层，水位比河床高 1.6 米。半透明、低粗糙度，靠 HDRI 环境反射出天光。
   法线贴图沿流向缓慢滚动模拟流水。绝对不要做实时反射（太贵）。

三、三处必须一起改
   1. 水磨坊现在离河 38 米，不临河，属于穿帮。把它挪到河边（约 -88, 62），水轮朝河。
   2. 河滩地现在的范围正好压在河面上，往东缩到河岸以东。
   3. 几何草的撒点要排除河道，否则水面上会浮一层草。

四、桥
   村西小路跨河的位置修一座漫水桥（西北旱地小河常见），桥面略高于常水位。

【自证】
- 从高处俯瞰截一张，能看到河道穿过村子西侧
- 第一人称走到河边截一张，看岸线是否平滑、水面有没有反光
- 用 probe.mjs 沿河取 5 个点，打印各自的河床高度，确认深度一致
- 明确回答：河里有没有草？水磨坊现在离河多远？河滩地还压不压河面？
```

**验收**：俯瞰有河；岸边没断崖；水里没草；水磨坊临河。

### P7 · 动物升级

```
接通用开头。

【本次只做】把家畜做得像动物，别的一律不动。目标是"可信的低模"，不是照片级。

现状问题：牛是胶囊体 + 方块头 + 四根圆柱腿，看着像一坨。

要改的（牛、羊、鸡都要）：
- 身体：保留主体形，但加起伏，牛要有肩峰
- 头：不要方块，改成带口鼻的椭球
- 脖子：加一段，牛粗短、羊细长
- 耳朵、尾巴：都要有，尾巴带末端毛球
- 腿：分上下两段，中间有关节感
- 毛色：不要纯色，背深腹浅

动画（只做这些，别贪）：
- 整体轻微走动（现在已有，保留）
- 牛和羊低头吃草，头能上下动
- 尾巴缓慢摆动

【硬约束 · 这条最重要】
每只动物必须合并成一到两个网格，不能拆成十几个零件。
16 只动物拆零件会多出近 200 个 draw call，性能白修。
做完必须报告：动物部分的 draw call 总数，不能超过改之前的 2 倍。

【自证】
- 第一人称走到牛棚截一张近景，我要能认出这是牛
- 报告动物部分的 draw call 数和改前对比
- 报告帧率和改前对比
```

**验收**：近看能认出是牛是羊；不卡。

【自证】

## 四、执行节奏

```
第 0 批   P0                      0.5 天    → git commit
第 1 批   P1 → P2                 1.5 天    → git commit + 截图存档
第 2 批   P3 → P4 → P5            3 天      → git commit + 体检表
第 3 批   P6 → P7 → P8 → P9       3 天      → git commit
收尾      P10                     0.5 天    → 打 tag、发版
```

**每批发完提示词，先看它贴的截图和探针输出，再看它说的"已完成"。** 顺序反了，你就是被它牵着走。
