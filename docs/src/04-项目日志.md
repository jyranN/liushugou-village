## 三、阶段一：需求澄清

### 3.1 起点

最初的信息是一条"用 AI 构建三维数字孪生可视化"的短视频，用户想照着做一个农业主题的。前几轮沟通一直在"农业数据大屏"的方向上，直到用户明确否掉：

> "不是农田数据大屏，是楚门的世界——我还可以设置季节天气，能拖时间轴，天气完全模拟现实。"

### 3.2 澄清后的需求

- 一个**虚构村落**（不是真实村庄的复刻），甘肃定西岷县风格
- 上帝视角俯瞰、可缩放、点任意物体弹档案、点空白关闭
- 第一人称摇杆 / WASD 行走
- 可拖时间轴，**1 分钟 = 1 天**（后续按体验改为 3 分钟）
- 天气由**真实历史数据**驱动：岷县 2025 全年
- 有夜晚、有季节
- 只在电脑上看
- **全程由 AI 完成，用户只负责验收**

### 3.3 数据可行性验证

先确认岷县 2025 年数据完整：Open-Meteo 归档 API 返回 8760 小时、365 天，无缺测。统计结果直接影响了后续设计：

- 气温 −19.5 ℃ ~ 28.7 ℃
- 降水 170 天、645 mm；降雪 34 天
- 年均云量 68%，**晴天只有 7 天、阴天 155 天**

结论：不能用"天气代码"渲染，必须用**连续云量**，否则画面八成时间灰蒙蒙。

- 绘制调用 758，三角面 15.4 万

### 4.3 踩坑

| 问题 | 根因 | 修法 |
|---|---|---|
| 树冠是明显多面体 | IcosahedronGeometry 非索引，顶点不共享，法线按面算 | 改用 SphereGeometry |
| 树冠发黑 | `map` 与 `color` 双重相乘 | 基色置白 |
| world.js 报 `treeSeq is not defined` | 引用了 data.js 的私有变量 | 改为从导出数组读取 |
| 无头浏览器截图总是空白 | `--screenshot` 在 load 时截，等不到 setTimeout | 自检改为同步执行 |

## 五、阶段三：M1.5 画面精修

### 5.1 目标

用户反馈"M1 画面非常粗糙，各种细节都不要放过"。

### 5.2 关键改动

- 后处理链：EffectComposer + RenderPass + SSAOPass + UnrealBloom + OutputPass
- 树木改为干 / 枝 / 叶三组 InstancedMesh，绘制调用从 752 降到个位数
- 地被草簇 2200 个实例化
- 民居补齐台基、墙裙、门框门楣、门槛、窗棂、窗台、檐口、墙帽、门楼、烟囱帽
- 新增电线杆与悬垂电线、水缸、石墩、晾衣绳（这一版的电线杆只存在于当时的中间版本，**没有进入现行代码**；v1.1 场景里没有电线杆。这是当时的状态，v1.2 的变化见 14.1）

### 5.3 经验

- **头顶的电线是中国乡村最强的识别符号**。当年一根都没有时，房子再准也不像村子。早期原型因此做过一版，但重构后没有保留；v1.1 的场景里仍然没有电线杆，这一条留在遗留事项里，不能写成"已恢复"。（当时结论；v1.2 源码已补杆线并进入单文件版，见 14.1）
- 叶簇贴图必须真镂空。早期椭圆数量 620 个铺满整张图，alphaTest 裁不出形状，树冠像一团绿雾。

### 6.1 目标

接入真实气象，让时间可停、可拖、可变速，昼夜与季节跟着走。

### 6.2 实现

- `environment.js`：数据 → 太阳位置 / 强度 / 色温、天空双色、云量、雾、曝光、物候绿度
- `ui.js`：时间条、暂停、拖动、日期与天气显示

### 6.3 踩坑

| 问题 | 根因 | 修法 |
|---|---|---|
| 云像一层贴纸，斜视拉丝 | 用平面云层做投影 | 云挂到天空球着色器，按球面坐标采样 |
| 季节变绿后荧光 | 颜色直接相乘导致过饱和 | 保持亮度的色调替换 |
| 远处树冠消失 | 叶片小于一个像素，被 mipmap 吃掉 | 按视距放大补偿，最多 3.2 倍 |
| 雾把村子吃掉 | 雾密度固定 | 按相机高度自适应衰减 |

## 七、阶段五：单文件离线版

### 7.1 起因

用户连续几次只看到截图，质问"你生成的只是图片啊"。这暴露了一个交付问题：中间过程一直在截图验证，但没有把**可交互的产物**交到用户手里。

### 7.2 方案

`tools/build-standalone.mjs`：esbuild 打成 IIFE，把 JS、CSS、气候 JSON、全部贴图以 data URI 内联成一个 HTML。

关键点：

- three 与 three/addons 必须用 esbuild 插件自定义解析，否则会打进两份 three 实例
- 气候数据走 `window.__CLIMATE_DATA`，因为 `file://` 下 fetch 被拦截
- 产物 1.5 MB（当时素材还少），双击即开

### 7.3 教训

**present_files 把 PNG 放第一位，用户会以为交付物就是图片。** 可交互产物必须排第一。

## 八、阶段六：实景素材与画质攻坚

### 8.1 目标

用户要求"像和平精英的画面"。

### 8.2 素材接入

- 素材源：Poly Haven（CC0），API 可取 diffuse / nor_gl / rough 的 1k–2k JPG
- HDRI 用 1k 田园全景，经 PMREM 生成环境贴图
- 下载：草地、瓦、砖、土路、麦田 HDRI

### 8.3 关键教训

| 问题 | 根因 | 修法 |
|---|---|---|
| 整幅画面发白发灰 | SSAOPass 内部重渲染场景，丢掉色调映射 | 换 GTAOPass |
| 阴影几乎消失 | `normalBias` 误设 0.6（0.6 米） | 改 0.035 |
| 接入 HDRI 后过曝 | 间接光被重复计算 | 压低 hemi / bounce / sunPower |
| 路面像水泥 | 碎石 roughnessMap 高光过强 | 丢掉 roughnessMap，固定 0.97 |

### 8.4 画质天花板的判断

明确告知用户：**用 Three.js 程序化几何达不到 3A 手游画质**，差距在建筑是盒子拼装、植被单一、无人物无载具。给出三条路：换引擎、缩小范围、走风格化。用户选择先试引擎。

## 十、阶段八：远景与近景细节

### 10.1 远山

| 问题 | 根因 | 修法 |
|---|---|---|
| 地形像浮岛 | 远山与地形没有衔接 | 内圈沿用 heightAt，出边界后混入山体 |
| 天空边缘一条直线切口 | 远山平面超出天球范围 | 天球 900→2400 米，相机 far 1400→3400 |
| 俯瞰出现迷彩斑块 | 远山与地形共面 z-fighting | 地形覆盖范围内下潜 |
| 仍残留不规则"雪斑" | 网格密度不同（20 m vs 3.26 m），插值曲率误差数米 | 下潜量加到 4 米 |

### 10.2 近景

- 叶片改为 4×4 曲面，横向微卷、叶尖下垂，重算法线
- 片元着色器用背光方向做透射近似，近看不再像纸片
- 枝条加粗、主枝缩短、叶簇分布外扩，解决"黑棍顶叶子"
- 院墙按段随机 UV 相位与镜像、逐墙色差、世界坐标雨痕，消除重复感
- 瓦面加世界坐标低频色差

### 10.3 一个反直觉的坑

**透明的"檐下 AO 面片"绝对不能进场景。** 半透明 ShaderMaterial 会污染 GTAO 的深度与法线预通道，整面墙出现黑白花斑。最终改为在墙体材质里按世界高度渐暗。

## 十一、阶段九：手感与昼夜连续性修复

### 11.1 用户反馈

> "时间速度太快了，还有缩放、前进这些功能卡顿不流畅，昼夜交替像 PPT 一样没有连贯性。"

### 11.2 昼夜像 PPT 的根因

`climate.sunAt()` 用 `Math.floor(hour)` 取整点，太阳高度与方位**一小时跳一格**。原始设定一分钟一天，等于每 2.5 秒跳一次，看起来就是幻灯片。

修法：新增 `sunVector(hour)`，用赤纬 + 时角 + 时差方程逐帧解析；同时把 `sample()` 的 `hourOfDay`、`dayOfYear` 全部改为小数，气温、云量、湿度、绿度、积雪一起连续化。

### 11.3 速度

- 四档：一天 = 6 分 / 3 分 / 1 分 / 20 秒，默认 3 分
- 速率本身做缓动，切档不弹跳
- 时间轴从 1000 格改为 35040 格（15 分钟/格），拖动不再一次跳 9 小时
- 拖动自动暂停、松手自动恢复

### 11.4 卡顿

| 措施 | 收益 |
|---|---|
| 阴影按需刷新（太阳角度触发，≤5 次/秒） | 省掉每帧一整遍全场景深度渲染，最大头 |
| 自适应分辨率 0.62–1.75 倍（v1.0 时的范围；v1.1 改为按画质档位，见 13.2） | 低配机器自动降档，不再固定 2 倍像素比 |
| MSAA 4→2，GTAO 采样 12/16→8/12 | 后处理开销下降约三成 |
| 悬停拾取限频 11 Hz | 移动鼠标不再卡 |
| 时间条 DOM 写入限频 9 Hz | 消除每帧重排 |
| 相机全部改为帧率无关阻尼 | 60 Hz 与 120 Hz 手感一致 |

### 11.5 顺带修掉的三个老 bug

1. **启动总是贴地**：`Number.isFinite(Number(qp.get('tx')))` 中 `Number(null) === 0`，永远命中调试分支，相机半径被设成 14 米。改为 `qp.has('tx')`。
2. **夜里树冠发绿光**：叶片的透光项没乘太阳强度，太阳落山后仍在自发光。乘上 `directionalLights[0].color` 的亮度后消失。
3. **阴影相机范围不生效**：改了正交范围却没调用 `updateProjectionMatrix()`。

### 11.6 视觉补充

- 天空加太阳圆盘、光晕、日落方向的方位角暖光
- 加月光补光（冷蓝 0.95，不投影），夜里有可读的轮廓
- 暮光补偿，黄昏不再直接掉黑

## 十三、v1.1 增补（11-07 ~ 11-08）

v1.0 交付后，又做了九轮增补。这一章按轮次记关键改动与踩坑，不重复 v1.0 的内容。

### 13.1 操作修正与降开销

用户反馈第一人称 A/D 反向、进入第一人称时镜头多转 180°。根因有两处：`enterWalk` 里 `yaw = atan2(...) + π` 多加了半圈；`_updateWalk` 的右向量写成了前向量的垂直分量而不是叉积。修法：

```js
this.yaw = Math.atan2(t.x - this.walk.x, t.z - this.walk.z);   // 去掉 + π
const wx = -ix * cos - iz * sin;                                 // R = F × (0,1,0)
const wz =  ix * sin - iz * cos;
```

`exitWalk` 的 `theta = yaw + π` 保持不变。probe 实测 W/S/A/D 点积为 1 / −1 / −1 / 1，朝向村中心夹角 0°。

## 十六、地形材质：把「一张贴图平铺 300 次」拆成三层（11-09）

### 16.1 先量，再定阈值

任务是「近景 5 m 内看不出明显重复」。确认前只读代码，定位到根因：整块 620×620 m 地形只有一张 `assets.grass`、`repeat=300`，全图同一个 2.07 m 周期；`patchSeason` 的 macro 只能调亮度，改不了图案。山体更糟——顶点色把同一张草地贴图乘成土黄与冷灰，A 版山顶截出来是一片橄榄绿，完全没有岩石。

阈值没有拍脑袋。先用只读 CDP 采样现有单文件版的 46,986 个顶点，实测：坡度中位 **0.011** / p90 **0.077**、曲率 p10 −0.0136 / p50 0 / p90 0.0132、山顶曲率中位 0.072。这条数据很关键——地形整体极缓，若按「常见陡坡 0.3」当岩石阈值，全图只有山顶几十个顶点命中、山会整片变绿。所以最终**以山体相对抬升 `f` 为主判据，坡度只作加速项**。

### 16.2 三层与权重

草 `assets.grass`（2.07 m）、土 `assets.road`（4.50 m，转 +27°）、石 `TEX.terrainRock()`（26.00 m，转 −41°）。周期比 1 : 2.17 : 12.6，互不成整数比。权重逐顶点算进 `aTerrW`（vec3，46,986 顶点 ≈ 564 KB）：

```
wRock = smoothstep(0.42,0.92,f) × (0.55 + 0.45·slopeW) + 0.35·slopeW·smoothstep(−0.10,0.60,curvN)
wSoil = 0.75·smoothstep(0.10,0.48,f)·(1−wRock) + 0.25·smoothstep(0.15,0.75,−curvN)·(1−wRock)
wGrass = 1 − wRock − wSoil
```

村内 `f=0` 纯草 100%、山脚 74/26/0、山腰 18/55/27、陡坡与山顶 7/21/72；逐顶点恒和为 1（实测 0.99999996–1.00000004）。顶点色只留海拔压暗与河床沙砾——原来那套 `SOIL`/`ROCK` 强色偏会与三层权重相乘、让裸土与岩石过饱和。

### 16.3 三个坑：map 乘两遍、摩尔纹、棋盘格

- **map 乘两遍**：第一版替换 `#include <map_fragment>` 时把 include 保留在替换串里，chunk 已经把 `diffuseColor` 乘过一次 map，我又乘一次 `_cG`，草地明显偏暗偏饱和。改成「替换」而非「追加」，自己完成基础层采样。
- **法线多 normalize**：`vec3(_nG.xy, 1.0)` 再 `normalize` 会把 `normalScale` 的效果削掉一截、把地面压平，近景反而更容易看出重复。改为沿用基础层 z、整体只 normalize 一次，`_w=(1,0,0)` 时与改动前逐字一致。
- **摩尔纹**：草层第二尺度先给了 61° 旋转 + 权重 0.30，两层方向不同的网格叠出明显斜向格子；降到 0.14 仍可见。最终改成**同向、不同周期、错相位**，格子消失。
- **棋盘格**：石层直接复用 `TEX.stone()`，那是给挡墙/台阶画的 34 px 砌块 + 2 px 暗缝，铺到山坡上远处混叠成整片棋盘，夜间与雪天尤其明显。新增 `terrainRock()`（多尺度 fbm + 细裂隙、无规则格子）后彻底消失。中间试过把周期从 12 m 放大到 20、42 m，格子只是变大、没有消失，**换贴图才是解**。
- **雪天网格**：雪只混了 `diffuseColor`，法线仍带石层凹凸，雪面透出方格网。把雪天的法线混合权重从 0.75 提到 0.95。

### 16.4 远山盖住了地形

排查「改了材质但山没变」花了很久：染红、染蓝、改 repeat、隐藏网格逐项试。最后靠三条证据定性——隐藏地形后画面变了（说明地形在渲染）、品红写死能出现（说明 shader 在跑）、包围盒查询显示只有地形与远山覆盖山体。结论：**远山网格内圈只按 `edge` 固定下潜 4 m，而它取的是 `baseHeight`（不含孤山），孤山抬升 58 m 时远山与地形齐平甚至顶出来，把整座地形孤山盖住**。这是原有缺陷，地形材质再怎么改山上都看不见。改为按 `hillLift` 加权补下潜（`4.0 × (1 − sm(edge/70)) + hillLift × 1.12`），村内 `hillLift = 0`、行为不变。

顺带记一个方法论教训：**低分辨率截图会骗人**。640×400 下地形贴图被 mipmap 压成平均色，看起来像「材质没生效」；换到 1280×800 并隐藏草簇后，A/B 差异一眼可见。后续地形类验收统一用 1280×800。

## 十七、作物物候：把「一整片绿」拆成五个状态（11-10）

### 17.1 现状与任务的三个差距

### 17.2 先算积温，再定参数

从 8760 条逐小时温度预计算 365 项逐日累积 GDD（基温 5 ℃），实测 2025 岷县：全年 **1885 ℃·d**；3/15→7/10 = 757（春小麦全生育期）、4/15→8/1 = 998（马铃薯）、4/15→10/1 = 1631（当归移栽到采收）。各作物的 `gddNeed` 就是按这些数字与档案里的采收期反推的，不是拍的。

首版把当归定成 1700，结果 10 月 15 日 14 块地全部留茬——因为 4/15 之后的积温已经 1715。改成 1730 后，当归 8/20 成熟、10/23 收割，与档案「10 月下旬采挖」对上。

### 17.3 五状态与四形态族

每块地算 `g = clamp((积温 − 播种日积温) / gddNeed, 0, 1.10)`，五个状态是 `g` 的区间，株高 / 密度 / 色相 / 留茬高度全是 `g` 的连续函数。密度用「逐实例固定随机阈值 + smoothstep」而不是布尔开关，出苗与收割时按顺序逐渐长出来 / 消失。

形态分四族：`tall` 玉米、`dense` 小麦/党参/柴胡、`low` 马铃薯/蔬菜/黄芪、`umbel` 当归。当归单独一族是因为它在岷县是道地药材：叶丛用「水平叶盘 + 两片竖直叶」（只用竖直薄片的话，平视是一条线、俯瞰是一条缝），抽薹后另起一层花葶与伞形花序，花序是 `TEX.cropUmbel()` 画的 128×128 程序化贴图。

每帧只写 14 个 float 到 `uFieldG[14]`，实例带 `aFieldIdx` 在顶点着色器里取自己的 `g`——5 万个实例逐帧遍历会直接吃掉帧率。

### 17.4 三个连锁问题

- **田面泛绿跟全局 `uGreen` 走**：10 月草还绿、收割完的田也绿，季节差异看不出来。改成按各块地的 `g` 算覆盖度与黄化。
- **草长在耕地里**：草簇的隐藏条件只有 `inProduction` 与 `inCivic`，没有耕地。10 月留茬后草还盖着田面，像作物从来没长过。新增 `inField()`，把实例缩放写 0（不插 `continue`，15 万株草位不重排）。
- **改种带来收入连锁**：4 块地改种后，`INCOME_RATES` 要补玉米 1400、小麦 1200，受影响 4 户的 `cropMain` 与 `income` 要同步，全村年收入从 139.9 变成 115.6 万元。`verify-cards.mjs` 的 `dominantCrop` 取亩数最大的作物，H-06 有两块不同作物的地时卡片要写「小麦」而不是「马铃薯、小麦」。

### 19.3 垂柳怎么做的

主枝第 1 段按 0.55–0.85 rad 上扬，之后每段用 `droopDir()` 把方向绕水平轴向下压 0.86 rad。第 3 段的仰角落在 −0.9 rad 附近（约 −40°），段长按 0.90 递减、半径按 0.70 递减。每一段末端往下挂 2–3 串叶簇，靠下的段挂 3 串，形成垂帘；柳叶用 `leafAspect [0.58, 1.32, 1]` 拉成细长形。柳树主枝从 3 根加到 5 根，垂枝才成势。

### 19.4 分配规则：纯函数，不取随机数

`pickSpeciesFor(x, z, seq)` 按区位返回树种：行道杨 70% / 榆 20% / 槐 10%；院落槐 40% / 榆 40% / 杏 10% / 杨 10%；河边每 6 棵留 1 棵杨、其余全柳。

**关键约束**：这个函数里不能取随机数。树的坐标、民居、场院、作物全串在同一条全局随机序列上，多取一个就会把后面所有布局整体推移，公共核心与生产空间的落位校验会全部失效。所以 `addTree()` 里仍保留一次 `rnd()` 调用对齐消耗，只是结果丢弃。

结果：杨 36、榆 25、槐 23、杏 5、柳 12（101 棵）；行道杨 69%、院落槐榆 83%、河边柳 92%。

### 19.5 可复现

树的随机数换成每棵树独立的 `treeRng(seed)`（mulberry32），种子 = 位置毫米哈希 ^ 序号。同一份数据每次加载长出来的枝与叶逐位一致；改一棵树的位置也不连累别棵。验收脚本连续两次加载同一页面，树干实例矩阵指纹 1976210033 与叶簇数 38943 完全相同。

### 19.6 三个坑

- **枝条比树干还粗**：主枝半径原来是树干顶部半径的 1.95 倍，dbh 64 的杨树主枝直径 0.55 m。原来叶簇密，看不出来；叶量一调低就露出几根「木棍」。改成 0.95 倍。
- **垂枝被冠顶叶簇淹没**：柳树 `clusters` 原来给 1.22，冠顶堆满叶子，垂帘完全看不见。降到 0.62，叶量转到垂枝的每一段末端。
- **四种轮廓区分度不够**：第一版杨冠 0.34、榆 0.66，两者都是"高瘦"容易混。杨压到 0.28（更窄更高）、榆压到 0.46 并让枝条外张、柳冠压扁到 0.32。

## 二十、野性层：山坡与田边的灌木和杂草（11-10）

### 20.1 任务与现状

任务说"山坡与田边太整洁"。读码确认：山坡只有地形材质的三层贴图（草/土/石），田边只有一条几何田埂，村后孤山从山脚到山顶一根植被都没有；近景地面除了 15 万株实体草就是裸贴图，缺"野生"的一层。

### 20.2 几何：叶卡 + 核心块

灌木是**两套几何合成一个**：3 片交叉叶卡 + 1 片顶盖（共 8 三角形，采样既有 `TEX.leafCard` 深色版）给近景的碎叶感，1 个二十面体核心块（20 三角形）给远景的体量。顶点带 `aCore` 属性（叶卡 0 / 核心 1），顶点着色器按实例到相机的距离把两者**此消彼长**：`transformed *= mix(1.0 − _lod, _lod, aCore)`——近处核心块缩到 0（藏起硬棱），远处叶卡缩到 0（只剩团块）。初版两套同时显示，近景全是绿色金字塔，就是这个塌缩修掉的。

杂草是 8 片细窄弧形叶：根宽 0.013 m → 梢 0.0025 m，二次外张、梢部微垂，纯顶点色不采样贴图。初版叶宽 0.048 m 且笔直，近看像一丛丛竖板（龙舌兰），重写才像丛生草。

### 20.3 撒点：六路权重 × 斑块 × 稀疏系数

密度 = 六路权重**取最大值**：陡坡 0.85（坡度 0.08–0.30）、孤山山体 0.70（抬升 2–12 m）、河岸带 0.90（外 12 m）、田埂带 0.55（两侧 2.5 m）、田边带 0.85（田界外 0.7–5.0 m）、村周 0.22（半径 22–70 m），平地底噪 0.10。再乘 fbm 斑块（频率 0.030，约 33 m 尺度的簇与空档）与 openness 稀疏系数（主路 2.2 m、巷道 1.6 m、院墙 3 m、场院 2 m 内趋近 0）。耕地、道路、场院、公共核心、河道、田埂路面全部排除——田里不长杂物、路上不立草。

随机数用独立 mulberry32（`treeRng(0x5C2B17)`），不消耗全局 `rnd`，每次加载撒点逐位一致。撒点在加载时一次性完成（约 19 万次拒绝采样、带 guard 防死循环），运行时每帧 0 CPU 开销。

### 20.4 季节两套配色

春夏青绿、秋冬枯黄褐，接既有 `seasonUniform`，不写死日期。**灌木走乘色**（`diffuseColor.rgb * 色带`），保住叶卡的明暗层次；**杂草走换色**——按亮度重建色相（luma → 色带映射）。初版杂草也走乘色，枯草被顶点色乘成一片惨白，这就是修法。积雪按局部高度扫白，与地形共用 `uSnow`。

### 20.5 顺坡倾斜

陡坡上灌木原来一根根直立插着。改为按地形梯度法线倾斜 65%（`slopeQuat`），落点下沉 0.12 m，迎坡侧不露悬空的根。

### 20.6 远景与性能
