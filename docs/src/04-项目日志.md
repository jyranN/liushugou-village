## 三、阶段一：需求澄清

### 3.1 起点

最初的信息是一条"用 AI 构建三维数字孪生可视化"的短视频，用户想照着做一个农业主题的。前几轮沟通一直在"农业数据大屏"的方向上，直到用户明确否掉：

> "不是农田数据大屏，是楚门的世界——我还可以设置季节天气，能拖时间轴，天气完全模拟现实。"

### 3.2 澄清后的需求

- 一个**虚构村落**（不是真实村庄的复刻），甘肃定西岷县风格
- 上帝视角俯瞰、可缩放、点任意物体弹档案、点空白关闭
- 第一人称摇杆 / WASD 行走
- 可拖时间轴，**1 分钟 = 1 天**（后续按体验改为 3 分钟）
- 天气由**真实历史数据**驱动：岷县 2025 全年
- 有夜晚、有季节
- 只在电脑上看
- **全程由 AI 完成，用户只负责验收**

### 3.3 数据可行性验证

先确认岷县 2025 年数据完整：Open-Meteo 归档 API 返回 8760 小时、365 天，无缺测。统计结果直接影响了后续设计：

- 气温 −19.5 ℃ ~ 28.7 ℃
- 降水 170 天、645 mm；降雪 34 天
- 年均云量 68%，**晴天只有 7 天、阴天 155 天**

结论：不能用"天气代码"渲染，必须用**连续云量**，否则画面八成时间灰蒙蒙。

## 四、阶段二：M1 静态村庄

### 4.1 目标

先让村子"立起来"：地形、道路、14 户民居、94 棵树、可点击的档案卡。

### 4.2 结果

- `village/` 工程建立：index.html + css + 6 个 JS 模块
- 14 户 / 94 树 / 16 牲畜 / 14 地块 / 144 个可点对象
- 自检：档案卡 7 字段、点空白关闭、第一人称眼高 1.68 米、0 报错
- 绘制调用 758，三角面 15.4 万

### 4.3 踩坑

| 问题 | 根因 | 修法 |
|---|---|---|
| 树冠是明显多面体 | IcosahedronGeometry 非索引，顶点不共享，法线按面算 | 改用 SphereGeometry |
| 树冠发黑 | `map` 与 `color` 双重相乘 | 基色置白 |
| world.js 报 `treeSeq is not defined` | 引用了 data.js 的私有变量 | 改为从导出数组读取 |
| 无头浏览器截图总是空白 | `--screenshot` 在 load 时截，等不到 setTimeout | 自检改为同步执行 |

## 五、阶段三：M1.5 画面精修

### 5.1 目标

用户反馈"M1 画面非常粗糙，各种细节都不要放过"。

### 5.2 关键改动

- 后处理链：EffectComposer + RenderPass + SSAOPass + UnrealBloom + OutputPass
- 树木改为干 / 枝 / 叶三组 InstancedMesh，绘制调用从 752 降到个位数
- 地被草簇 2200 个实例化
- 民居补齐台基、墙裙、门框门楣、门槛、窗棂、窗台、檐口、墙帽、门楼、烟囱帽
- 新增电线杆与悬垂电线、水缸、石墩、晾衣绳（这一版的电线杆只存在于当时的中间版本，**没有进入现行代码**；v1.1 场景里没有电线杆）

### 5.3 经验

- **头顶的电线是中国乡村最强的识别符号**。一根都没有时，房子再准也不像村子。早期原型因此做过一版，但重构后没有保留；v1.1 的场景里仍然没有电线杆，这一条留在遗留事项里，不能写成"已恢复"。
- 叶簇贴图必须真镂空。早期椭圆数量 620 个铺满整张图，alphaTest 裁不出形状，树冠像一团绿雾。

## 六、阶段四：M2 时间与天气

### 6.1 目标

接入真实气象，让时间可停、可拖、可变速，昼夜与季节跟着走。

### 6.2 实现

- `data/minxian-2025-raw.json`：8760 小时 + 365 天
- `climate.js`：`Climate` 负责取样与插值、日出日落、太阳角度；`Clock` 负责推进与调速
- `environment.js`：数据 → 太阳位置 / 强度 / 色温、天空双色、云量、雾、曝光、物候绿度
- `ui.js`：时间条、暂停、拖动、日期与天气显示

### 6.3 踩坑

| 问题 | 根因 | 修法 |
|---|---|---|
| 云像一层贴纸，斜视拉丝 | 用平面云层做投影 | 云挂到天空球着色器，按球面坐标采样 |
| 季节变绿后荧光 | 颜色直接相乘导致过饱和 | 保持亮度的色调替换 |
| 远处树冠消失 | 叶片小于一个像素，被 mipmap 吃掉 | 按视距放大补偿，最多 3.2 倍 |
| 雾把村子吃掉 | 雾密度固定 | 按相机高度自适应衰减 |

## 七、阶段五：单文件离线版

### 7.1 起因

用户连续几次只看到截图，质问"你生成的只是图片啊"。这暴露了一个交付问题：中间过程一直在截图验证，但没有把**可交互的产物**交到用户手里。

### 7.2 方案

`tools/build-standalone.mjs`：esbuild 打成 IIFE，把 JS、CSS、气候 JSON、全部贴图以 data URI 内联成一个 HTML。

关键点：

- three 与 three/addons 必须用 esbuild 插件自定义解析，否则会打进两份 three 实例
- 气候数据走 `window.__CLIMATE_DATA`，因为 `file://` 下 fetch 被拦截
- 产物 1.5 MB（当时素材还少），双击即开

### 7.3 教训

**present_files 把 PNG 放第一位，用户会以为交付物就是图片。** 可交互产物必须排第一。

## 八、阶段六：实景素材与画质攻坚

### 8.1 目标

用户要求"像和平精英的画面"。

### 8.2 素材接入

- 素材源：Poly Haven（CC0），API 可取 diffuse / nor_gl / rough 的 1k–2k JPG
- HDRI 用 1k 田园全景，经 PMREM 生成环境贴图
- 下载：草地、瓦、砖、土路、麦田 HDRI

### 8.3 关键教训

| 问题 | 根因 | 修法 |
|---|---|---|
| 整幅画面发白发灰 | SSAOPass 内部重渲染场景，丢掉色调映射 | 换 GTAOPass |
| 阴影几乎消失 | `normalBias` 误设 0.6（0.6 米） | 改 0.035 |
| 接入 HDRI 后过曝 | 间接光被重复计算 | 压低 hemi / bounce / sunPower |
| 路面像水泥 | 碎石 roughnessMap 高光过强 | 丢掉 roughnessMap，固定 0.97 |

### 8.4 画质天花板的判断

明确告知用户：**用 Three.js 程序化几何达不到 3A 手游画质**，差距在建筑是盒子拼装、植被单一、无人物无载具。给出三条路：换引擎、缩小范围、走风格化。用户选择先试引擎。

## 十、阶段八：远景与近景细节

### 10.1 远山

| 问题 | 根因 | 修法 |
|---|---|---|
| 地形像浮岛 | 远山与地形没有衔接 | 内圈沿用 heightAt，出边界后混入山体 |
| 天空边缘一条直线切口 | 远山平面超出天球范围 | 天球 900→2400 米，相机 far 1400→3400 |
| 俯瞰出现迷彩斑块 | 远山与地形共面 z-fighting | 地形覆盖范围内下潜 |
| 仍残留不规则"雪斑" | 网格密度不同（20 m vs 3.26 m），插值曲率误差数米 | 下潜量加到 4 米 |

### 10.2 近景

- 叶片改为 4×4 曲面，横向微卷、叶尖下垂，重算法线
- 片元着色器用背光方向做透射近似，近看不再像纸片
- 枝条加粗、主枝缩短、叶簇分布外扩，解决"黑棍顶叶子"
- 院墙按段随机 UV 相位与镜像、逐墙色差、世界坐标雨痕，消除重复感
- 瓦面加世界坐标低频色差

### 10.3 一个反直觉的坑

**透明的"檐下 AO 面片"绝对不能进场景。** 半透明 ShaderMaterial 会污染 GTAO 的深度与法线预通道，整面墙出现黑白花斑。最终改为在墙体材质里按世界高度渐暗。

## 十一、阶段九：手感与昼夜连续性修复

### 11.1 用户反馈

> "时间速度太快了，还有缩放、前进这些功能卡顿不流畅，昼夜交替像 PPT 一样没有连贯性。"

### 11.2 昼夜像 PPT 的根因

`climate.sunAt()` 用 `Math.floor(hour)` 取整点，太阳高度与方位**一小时跳一格**。原始设定一分钟一天，等于每 2.5 秒跳一次，看起来就是幻灯片。

修法：新增 `sunVector(hour)`，用赤纬 + 时角 + 时差方程逐帧解析；同时把 `sample()` 的 `hourOfDay`、`dayOfYear` 全部改为小数，气温、云量、湿度、绿度、积雪一起连续化。

### 11.3 速度

- 四档：一天 = 6 分 / 3 分 / 1 分 / 20 秒，默认 3 分
- 速率本身做缓动，切档不弹跳
- 时间轴从 1000 格改为 35040 格（15 分钟/格），拖动不再一次跳 9 小时
- 拖动自动暂停、松手自动恢复

### 11.4 卡顿

| 措施 | 收益 |
|---|---|
| 阴影按需刷新（太阳角度触发，≤5 次/秒） | 省掉每帧一整遍全场景深度渲染，最大头 |
| 自适应分辨率 0.62–1.75 倍（v1.0 时的范围；v1.1 改为按画质档位，见 13.2） | 低配机器自动降档，不再固定 2 倍像素比 |
| MSAA 4→2，GTAO 采样 12/16→8/12 | 后处理开销下降约三成 |
| 悬停拾取限频 11 Hz | 移动鼠标不再卡 |
| 时间条 DOM 写入限频 9 Hz | 消除每帧重排 |
| 相机全部改为帧率无关阻尼 | 60 Hz 与 120 Hz 手感一致 |

### 11.5 顺带修掉的三个老 bug

1. **启动总是贴地**：`Number.isFinite(Number(qp.get('tx')))` 中 `Number(null) === 0`，永远命中调试分支，相机半径被设成 14 米。改为 `qp.has('tx')`。
2. **夜里树冠发绿光**：叶片的透光项没乘太阳强度，太阳落山后仍在自发光。乘上 `directionalLights[0].color` 的亮度后消失。
3. **阴影相机范围不生效**：改了正交范围却没调用 `updateProjectionMatrix()`。

### 11.6 视觉补充

- 天空加太阳圆盘、光晕、日落方向的方位角暖光
- 加月光补光（冷蓝 0.95，不投影），夜里有可读的轮廓
- 暮光补偿，黄昏不再直接掉黑

## 十三、v1.1 增补（11-07 ~ 11-08）

v1.0 交付后，又做了九轮增补。这一章按轮次记关键改动与踩坑，不重复 v1.0 的内容。

### 13.1 操作修正与降开销

用户反馈第一人称 A/D 反向、进入第一人称时镜头多转 180°。根因有两处：`enterWalk` 里 `yaw = atan2(...) + π` 多加了半圈；`_updateWalk` 的右向量写成了前向量的垂直分量而不是叉积。修法：

```js
this.yaw = Math.atan2(t.x - this.walk.x, t.z - this.walk.z);   // 去掉 + π
const wx = -ix * cos - iz * sin;                                 // R = F × (0,1,0)
const wz =  ix * sin - iz * cos;
```

`exitWalk` 的 `theta = yaw + π` 保持不变。probe 实测 W/S/A/D 点积为 1 / −1 / −1 / 1，朝向村中心夹角 0°。

同一轮降开销：`MAX_SCALE` 1.75→1.25、GTAO 默认关（仅 `?ao=1`）、阴影 3072→2048、PCFSoft→PCF、曝光 1.16→1.20。踩到的坑：曝光在 `environment.js` 里每帧被 `world.update()` 覆盖，改 `main.js` 初值无效，必须改环境层的曝光曲线。

### 13.2 画质三档与天气预设

画质档不是只改分辨率，而是四件事一起切：像素比、GTAO、泛光、阴影贴图边长。换阴影尺寸必须先 `dispose()` 旧贴图并置 `shadow.map = null`，否则 three 不会重建。

天气预设从 8760 条记录现算，不写死日期。四个时刻最终落在 7-30 15:00（晴）、6-03 13:00（阴）、9-05 02:00（雨）、3-05 11:00（雪）。踩坑：自适应分辨率会把用户选的 1.25 偷偷降到 0.62，改成“档位即实值，只在 <20 FPS 时降到 90% 兜底”。

### 13.3 村东山与山神庙

山体中心 (170,20)、半径 75/68、顶 58 米。`heightAt` 里叠加 `hillLift`，用旋转椭圆 + `sm01` 二次衰减 + fbm + 放射冲沟；顶点色草→土黄→岩石，与“按海拔压暗”合并在同一循环，避免山顶发暗。

庙在 (140,20) 的 4.8 米台地上，台面 45.166 米，40 级石阶逐级按 `heightAt` 落地，庙前老槐 T-095 单独一块树盘台地。阴影相机扩到 180 米见方（near 60 / far 520，中心 (70,0)），否则庙不投影。

坑：L-14 梁上地的东缘实际到 x=103.09，山脚会压 0.347 米；没有放大山体半径，而是在 L-14 窗口内把抬升削到 ≤0.04 米再平滑接回。全村落位检查 161 个对象（这是加石墩之前的数量），被山压的为 0。

### 13.4 村西开河

河道从 (-105,-130) 到 (-98,130)，中段双正弦摆动乘 `sin²(πt)`，端点位移与导数归零；河宽 8 米、河床 −2.2 米、水位 −0.6 米、岸坡二次衰减。水面单独一层，`envMapIntensity 2.8`、`roughness 0.075`、`opacity 0.70`，反射直接取 `scene.environment`，**没有 Reflector / SSR**；法线每帧滚 `offset.y`。

三处连带改动：水磨坊从 (-62,62) 移到 (-88,62)，水轮朝西，轮缘距河心 4.42 米；L-06 河滩地缩到 (-76,96)、20×24，西缘离河心 11.57 米；几何草撒点排除河道。另查出需求没点名的 L-01、L-09 也压河，一并东缩；T-083/T-090 两棵树原本在河心/岸坡，推到东岸。

桥在 z=18，桥面 −0.30 米，只比常水位高 0.30 米，无栏杆，汛期可漫水；构件合并 1 个 Mesh，`walkHeightAt()` 让第一人称能踏上去。

### 13.5 村口树下设施

老杨树下 5 只八棱石墩（D-01…D-05），坐高 0.398–0.478 米，围树干 2.35–2.79 米不规则一圈；老槐下石碾（N-01），碾盘直径 2.4 米、碾磙 + 木架；院墙外 3 处水窖（W-01…W-03），石砌窖台 + 下沉窖壁 + 铸铁盖 + 辘轳架。

坑一：`CylinderGeometry` 以几何中心为原点，第一版按柱底平移，石墩一半埋在地下，实测坐高只剩 0.19–0.24 米；改成“柱底 + 半个坐高”。坑二：石墩顶面用扇形 UV，贴图在中心汇聚成“井盖纹”，改成 xz 平面投影。坑三：水窖铸铁盖完全盖住窖口，看不出内凹，改成半开、盖子挪到窖台南侧地上。

### 13.6 家畜重做

牛/羊/鸡全部重做：躯干椭球 + 肩峰、脖子单独一段、椭球头 + 口鼻 + 耳 + 角/冠、两段腿 + 关节球、尾巴 + 毛球；背深腹浅写入顶点色。每只合并成“身体 1 Mesh + 头 1 Mesh”，头绕脖子根低头吃草，尾巴用 `aTail` 顶点权重在着色器里摆。

draw call 从 104 降到 32（0.31 倍）。截图时发现随机朝向经常只拍到屁股，最终用“临时把目标牛转向、相机放南侧 4.6 米”的标准侧视来验证；这是取景手段，不改游戏内行为。

### 13.7 四处打磨

- **路面**：5 条支路原来共用 0..1 UV，砖纹被拉成广场大砖；按世界尺寸重排 UV（约 2 米一个周期），叠世界坐标低频色差，粗糙度 0.99。
- **草地**：原 shader 把每根草的亮度归一化，根深尖浅被抹平；改成保留色相、单独乘回亮度梯度。另加 5 万根近景草（半径 34 米），近处密度约 42 根/㎡。
- **树干**：顶点着色器在 `instanceMatrix` 之后按 `transformed.y²` 加 0.35–0.60 米弯曲，枝条与叶簇按同一偏移跟随；主枝 5→3 根、二级枝 3 根/主枝。
- **民居**：找到“门窗没有框”的真正原因——`doorHole` / `hole` 是 0.26–0.30 米厚的实心黑盒，把门板、玻璃、窗框、窗棂整个包住。改成 0.02 米薄暗片；门框加粗、门板换木纹 + 2 条竖槽、窗棂加密、檐椽 17→23 根、补三级台阶。14 户的构件合并成 2 个 InstancedMesh。

### 13.8 自动巡游

6 个镜头、约 32.5 秒：村口两树 → 主路 → 院门 → 晒场 → 山腰庙门 → 拉高俯瞰。低机位每帧锁 `heightAt + 1.8`，最后一段才升空；转场 `easeInOutCubic`，每段一行字幕；巡游中锁键盘/鼠标，Esc 或点任意处中断；开始前若在第一人称先 `exitWalk()`。

坑：山腰庙在 45 米台地上，台地边缘像挡墙，从山脚平视完全看不到；爬到 x=130.9 仍被挡，x≥133.5 才露出来，而台地内距庙门只剩 3 米，退不开。最终第 5 段改成在台地边缘横移拍庙门近景，庙顶留给第 6 段升空后看。
