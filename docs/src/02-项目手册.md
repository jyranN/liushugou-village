# 柳树沟村 · 数字村落 项目手册

## 一、项目概述

### 1.1 背景

项目要做一个"可漫游、可干预"的三维村庄：既能像看沙盘一样俯瞰全村、点开每一栋房子看档案，也能切到第一人称走进去；时间可以拖、天气要是真的、昼夜要连续。用一句话概括目标——**一个"楚门的世界"式的数字村庄：看起来是布景，但每一阵风、每一场雪都有出处。**

### 1.2 项目定位

| 维度 | 定位 |
|---|---|
| 地域原型 | 甘肃省定西市岷县，岷山北麓川地聚落 |
| 村落性质 | 虚构，106 户行政村中的核心聚落片段，渲染 14 户 |
| 核心体验 | 上帝视角档案浏览 + 第一人称漫游 + 可拖时间轴 |
| 数据驱动 | 岷县 2025 年全年 8760 小时真实气象 |
| 交付形态 | 单文件离线 HTML（约 15 MB），双击即用 |
| 技术路线 | Three.js r160 + 自研着色器，桌面浏览器 |

## 四、关键技术

### 4.1 连续太阳位置解算

这是"昼夜不像 PPT"的根本。

早期实现按整点取太阳高度（`Math.floor(hour)`），太阳一小时跳一格；当"一分钟一天"时，每 2.5 秒画面就闪一次。现在改为逐帧解析：

- 太阳赤纬：`dec = 0.409·sin(2π(doy-80.5)/365.24)`
- 时差方程：`eot = 9.87sin2B − 7.53cosB − 1.5sinB`
- 真太阳时正午：`noon = 12 + (120° − 104.04°)/15 − eot/60`
- 时角：`H = (hourOfDay − noon)·15°`
- 高度：`sinAlt = sinφ·sinδ + cosφ·cosδ·cosH`
- 方位：由地平坐标转世界坐标，得到单位方向向量

纬度 φ = 34.4367°、经度 104.0417° 写死在 `climate.js` 顶部。经实测：2025 年 5 月 11 日日出 06:10、日落 19:51，正午太阳高度 68.6°，与气象数据一致。

同一套公式反解日出日落，保证光照与时间显示自洽。

### 4.2 真实气象驱动

岷县 2025 年**晴天只有 7 天、阴天 155 天**，年均云量 68%。这决定了不能用"天气代码"渲染，必须用**连续云量**驱动天空覆盖度：

```
uCoverage = clamp(1.02 − cloudFraction × 0.84, 0.12, 1.0)
```

云层挂在天空球着色器上，按球面坐标采样两层噪声，而不是贴一张平面云图——平面云在低视角会透视拉丝。

气温、湿度、降水、风速都在整点之间线性插值，避免整点跳变。

### 4.3 季节物候着色

季节不能用"换贴图"实现，否则整片山坡会像开关一样突变。做法是给地面、草、叶三套材质注入 `uGreen` 统一变量：

- 绿度曲线：`green = smoothstep(72,132,doy) × (1 − smoothstep(282,328,doy))`
- 地面混合权重 0.46，草 0.86，叶 0.84
- 关键细节：**保持亮度的色调替换**，而不是颜色相乘

```glsl
float lum = dot(diffuseColor.rgb, vec3(0.299,0.587,0.114));
vec3 summer = vec3(0.205,0.375,0.132) * (0.62 + lum*1.18);
diffuseColor.rgb = mix(diffuseColor.rgb, summer, uGreen*0.84);
```

直接用乘法会让绿色过饱和、发荧光。

### 4.4 实例化植被

| 对象 | 数量 | 绘制调用 |
|---|---|---|
| 草叶（基础层） | 15 万 | 1 |
| 草叶（近景层） | 5 万 | 1 |
| 作物 | 约 4.5 万株 | 1 |
| 树干 | 95 | 1 |
| 树枝 | 数百 | 1 |
| 树叶 | 数万 | 1 |
| 家畜 | 16 只 | 32（每只身体 + 头） |

单个草叶是上宽下窄、带弯曲的三角带；叶片是 4×4 细分的曲面（横向微卷、叶尖下垂），并在片元着色器里用背光方向做透射近似，近看不像纸片。

远处植被只有亚像素，必须按视距放大补偿（`smoothstep(30,170)` 最多 3.2 倍），否则会在 mipmap 里被"吃掉"。

### 4.5 后处理链

```
RenderPass → GTAOPass → UnrealBloomPass(0.22/0.55/0.94) → OutputPass(ACES)
```

选 GTAO 而不是 SSAO 的原因很实际：SSAO 会自己重渲染一遍场景，丢掉色调映射，整幅画面发灰。GTAO 只做屏幕空间遮蔽，配合 ACES 输出，对比度正常。

Bloom 强度压得很低（0.22），只让天空和夜间灯光轻微溢出，避免"手游光污染"。

### 4.6 按需阴影与自适应分辨率

这两项是"操作不卡"的关键。

**按需阴影**：太阳每转过约 0.09°、且距上次刷新超过 0.2 秒才重画 shadow map（最多 5 次/秒）。省下的是一整遍全场景深度渲染——这是单帧里最贵的一步。

**自适应分辨率**：v1.1 改成“档位即实值”的兜底逻辑——启动 2.5 秒后每 0.8 秒统计一次平均帧率，只有低于 20 FPS 才在当前档位的 90% 以内降一点（每次 0.12），高于 45 FPS 再升回档位值（每次 0.07），两次调整至少间隔 1 秒。这样用户选「均衡」不会被偷偷降到 0.62。后处理缓冲同步跟随，避免 AO 与主画面分辨率错位。

### 4.7 雨雪独立场景

雨雪粒子不放进主场景，而是单独一个 `weatherScene`，在主渲染完成后叠加。原因是半透明粒子会污染 GTAO 的深度/法线预通道，在墙面留下黑白花斑。同样的坑还出现在"檐下 AO 面片"上——最终改为在墙体材质里按高度渐暗，而不是贴透明面片。

### 4.8 河道地形：在高度场里“挖”一条河

河道不是贴在地表的一层水，而是真的把地形切下去：

- 中心线从 (-105,-130) 到 (-98,130)，中段叠加两组不同频率的正弦（3.4·sin(0.019z) + 1.5·sin(0.047z)），外面乘 `sin²(πt)` 包络，端点位移与导数都归零，所以不会出现折角，也不会笔直像水渠。
- 河槽到岸顶的半宽 6 米，河谷影响半宽 9 米；河床恒定标高 −2.2 米，水位 −0.6 米。岸坡用 `sm01` 二次衰减，横截面按 0.5 米步长扫描，最大相邻高差 0.27–0.34 米，没有断崖。
- 地形网格只在 x∈[−118,−82] 把横向分段加密到 0.54 米，其余维持 3.26 米；净增约 1 万顶点，draw call 不变。
- 河床顶点色单独染成沙砾土黄，浅水能透出河底。

沿河 5 个 probe 点（z = −120 / −60 / 0 / 60 / 120）实测河床都是 −2.200 米、岸顶都是 0.000 米、下切 2.200 米、水位 −0.600 米、水深 1.600 米，完全一致。

### 4.9 山体与台地：抬升与压平要一起做

村东孤山用椭圆高斯式抬升叠加在原始高度场上：

- 中心 (170,20)，长短半径 75 / 68 米，旋转 −0.10 弧度，山顶抬升 58 米；山脚 x=95 处抬升为 0，山顶 x=170 为 58.000。
- 衰减用 `sm01` 的二次曲线，再叠加 fbm 噪声、放射状冲沟和北侧山梁，避免“馒头山”。
- 山体顶点色按抬升比例做三段混合：草 → 土黄 → 岩石，并与原来的“按海拔压暗”合并在同一个循环里，避免山顶发暗。
- 庙基与庙前老槐各有一块 `PADS` 台地：庙基 (140,20)、半径 4.8 米、过渡 14 米，台面标高 45.166 米；树盘 (147,28)、半径 2.6 米、过渡 7 米。40 级石阶按 `heightAt` 逐级落地。
- 阴影相机范围从原来的村域扩到 180 米见方（near 60 / far 520，中心 (70,0)），同时盖住村子与东山，否则山上的庙不会投影。

draw call 净增 8 个（庙按材质合批 7 个 + 石阶 1 个）。

### 4.10 水面：只用环境贴图，不做实时反射

水面是独立一层 `Mesh`，不是地形的一部分：

- 水位 −0.6 米，沿河道生成一条带状网格；`roughness 0.075`、`metalness 0.34`、`envMapIntensity 2.8`、`opacity 0.70`、`depthWrite false`。
- 反射直接取 `scene.environment`（现有田园 HDRI 经 PMREM 生成的 envMap），**没有 Reflector、没有 SSR、没有 CubeCamera 每帧重渲染**——实时反射在这个场景里太贵。
- 法线贴图复用现有 `TEX.water()`，每帧只滚 `offset.y`，模拟顺流而下的细碎波纹。
- 在 `onBeforeCompile` 里加了一项掠射角天光：按视角与法线的菲涅耳项，把 `skyUniforms` 的当前天色叠到水面上，所以近景能看到一串流动的亮斑，而不是一块哑光蓝板。
- 水面 `renderOrder = 2`，在 GTAO 之后绘制；精致档开 GTAO 时也没有黑斑或深度打花。

### 4.11 家畜：每只两个网格

原来的牛是“胶囊 + 方块头 + 四根圆柱腿”，每只 6–8 个 Mesh，16 只共 104 个 draw call。v1.1 重做为可信低模：

- 每只动物只有两个 Mesh：**身体**（躯干 + 肩峰 + 四条两段腿 + 尾巴 + 毛球）和**头**（脖子 + 椭球头 + 口鼻 + 耳 + 角/冠 + 眼）。
- 同种动物共享几何缓存，材质从“每个纯色材质 + 牛角单独材质”合并成 **1 个顶点色材质**；毛色按背深腹浅写入顶点色。
- 头是独立 Mesh，pivot 在脖子根，绕 z 轴周期下压做低头吃草（牛、羊约 24 秒一个慢周期，鸡快速啄食）。
- 尾巴用顶点属性 `aTail` 标记权重，材质 `onBeforeCompile` 按 `uTime` 缓慢左右摆，相位取世界坐标，16 只不同步。
- 结果：动物部分 draw call **104 → 32**，是改前的 0.31 倍；三角形数增加不多，观感从“一坨”变成能认出牛、羊、鸡。

## 六、视觉与体验设计

### 6.1 光照曲线

| 时段 | 判据 | 表现 |
|---|---|---|
| 白天 | 太阳高度 > 11° | 直射为主，天光 0.34，曝光 0.94 |
| 暮光 | −6° ~ 11° | 曝光抬到 1.0 以上，天光转暖，路灯与窗灯渐亮 |
| 夜晚 | 太阳低于 −6° | 月光 0.95 冷蓝补光，天光 0.13，曝光 0.74 |

黄昏最容易翻车：如果只按太阳高度线性衰减，画面会在半小时内从白天直接掉进黑夜。所以加了**暮光补偿** `twi = exp(−(sinAlt/0.13)²)`，在太阳贴地时抬高天光、曝光与环境反射强度；同时天空用独立的 `skyF` 曲线——地面先暗、天还亮，才有剪影感。

### 6.2 天气表现

| 天气 | 表现 |
|---|---|
| 晴 / 少云 | 云覆盖度低，太阳硬，阴影清晰 |
| 阴 | 云覆盖度接近 1，天空压灰，阴影变软 |
| 雨 | 1300 条雨丝、路面变暗、雾加浓 |
| 雪 | 900 个雪点、72 小时累计积雪覆盖屋顶与地面、气温回升后融化 |
| 雾 | 湿度 > 78% 时雾密度上升 |

界面上的「晴 / 阴 / 雨 / 雪」不是写死日期，而是每次启动时从 8760 条记录里现算：晴取“云量 <10%、无降水、9–16 点、夏季最热”，阴取“云量 >85%、无降水、夏季正午前后”，雨取“全年降水量最大的一小时”，雪取“气温 <0℃ 时雪量最大”。换一份数据文件，四个按钮会自动落到新数据里对应的极值时刻。当前数据算出的四个时刻是：

| 预设 | 时刻 | 依据 |
|---|---|---|
| 晴 | 2025-07-30 15:00 | 云量 2%，26.4℃ |
| 阴 | 2025-06-03 13:00 | 云量 100%，10.8℃ |
| 雨 | 2025-09-05 02:00 | 降水 8.2 mm/h（全年最大，夜间） |
| 雪 | 2025-03-05 11:00 | 降雪 0.63 cm，−0.5℃ |

### 6.3 相机与操作手感

- 旋转：时间常数约 50 ms（`1−exp(−dt·20)`），跟手但不硬切
- 缩放：约 110 ms（`k=9`），滚轮按 `deltaMode` 归一化，触控板小增量不会被放大
- 注视点：约 180 ms（`k=5.5`），聚焦时有推进感
- 行走：起步 110 ms、收步 80 ms，Shift 加速时视野从 68° 推到 74°
- 巡游：每段用 `easeInOutCubic`，段内缓入缓出；段与段之间硬切，靠字幕 120 ms 淡出淡入过渡

所有阻尼都用 `1−exp(−dt·k)`，与帧率无关——60 Hz 和 120 Hz 上手感一致。

## 七、性能设计

### 7.1 预算

| 项目 | 取值 | 说明 |
|---|---|---|
| 渲染倍率 | 1.0 / 1.25 / 1.5 | 对应流畅 / 均衡 / 精致；自适应只在 <20 FPS 时降到档位 90% |
| MSAA | 2× | 半浮点缓冲，2× 足够 |
| 阴影贴图 | 1024² / 2048² / 3072² | 按画质档；覆盖 180 米见方（含东山） |
| 阴影刷新 | ≤5 次/秒 | 太阳角度触发 |
| GTAO 采样 | 8 / 12 | 仅精致档开启，比初版 12 / 16 低一档 |
| 三角面 | 约 307 万 | 含实例化草叶与作物，1280×720 俯瞰实测 |
| Draw call | 约 992 | 同上机位；v1.0 为 1057 |

### 7.2 优化清单

1. 阴影按需刷新（最大收益）
2. 植被全部实例化，草地 20 万株只占 2 个 drawcall（基础层 + 近景层）
3. 家畜每只合并成 2 个 Mesh，16 只从 104 个 drawcall 降到 32 个
4. 民居门窗构件按“一套几何 + 14 个实例矩阵”合并，只加 2 个 drawcall
5. 石墩 5 只合并 1 个 Mesh；水窖按石/铁/木三种材质各合并 1 个
6. 悬停拾取限频到 11 Hz，且拖动时不做
7. 时间条 DOM 写入限频到 9 Hz，文字没变不写
8. 积雪/湿润按 1/12 小时缓存，省掉每帧 28 次气象取样
9. 后处理尺寸跟随渲染倍率，避免高分辨率下的隐性超采样

### 7.3 实测

用 git 检出 v1.0 与当前 v1.1 各起一个本地服务，同一台机器、同一机位（村中心 120 米环视，phi 0.9）、同一分辨率 1280×720、固定像素比 1、精致档，测同一段脚本：

| 指标 | v1.0 | v1.1 | 变化 |
|---|---|---|---|
| 可点对象 | 160 | 170 | +10 |
| Draw call | 1057 | 992 | **−65** |
| 三角面 | 271 万 | 307 万 | +13% |
| FPS（单次会话三轮中位） | 29.2 | 23.3 | 受热降频影响，见下 |
| FPS（交错 A/B，各两轮） | 26.6 / 29.9 | 22.0 / 30.6 | 区间重叠 |

**结论**：v1.1 比 v1.0 多 13% 三角面（近景草、河道、山体），但少 65 个 draw call（家畜合并 −72，新增内容 +20，其余为合批差异）。无头 Edge 在这台机器上会热降频，同一版本两轮能差 7 FPS，因此两个版本的 FPS 差异落在测量噪声里，不能宣称“更快”或“更慢”；能确证的是 draw call 净减少。

真机回归（默认均衡档）：170 个可点对象全部命中、档案卡 7 行、第一人称眼高 1.68 米、雪景正常、控制台 0 报错，QA 记录 57–60 FPS。

## 九、局限与后续规划

### 9.1 已知局限

- **没有人物**：村里只有牲畜，没有村民，缺少生活气息
- **没有电线杆与架空线**：早期原型里有一版，但没有进入重构后的现行代码；当前场景中一根都没有
- **建筑是构件拼装**：由盒子与曲面组合，不是高模，贴到墙面近看能看到接缝
- **碰撞是圆形近似**：贴着墙走会有轻微穿插感
- **无音频**：没有风声、鸟叫、脚步
- **仅桌面端**：触屏体验不完整
- **气象是历史数据**：不能接实时天气（要接需要改数据层）
- **河道是高度场下切 + 平面水面**：没有流量、冲刷、汛期水位变化，桥面固定在高程 −0.30 米
